# 内置浏览器登录与字幕

## 能力边界

Codex 内置浏览器与电脑上的 Chrome/Edge、旧 `scripts/login.py` 启动的 Playwright 浏览器是不同会话。用户在内置浏览器登录后，可以继续读取该页面开放的内容；Python 的 yt-dlp 不会因此自动获得 Cookie。不要读取 Cookie 数据库、导出凭证或调用不存在的 Cookie API 来桥接它们。

本环境使用 `mcp__cua_repl.js`：先按工具要求初始化，阅读返回的浏览器文档，之后只使用当前明确提供的接口。不要用终端、CDP、另起 Playwright 或页面中的任意网络请求绕过浏览器工具。

## 本地 B站采集器

B站完整 BV 链接默认使用项目本地采集器，也可显式运行 `fetch.py '<BV视频链接>' --local-browser`。这是独立的本地 Chrome 会话，不读取或桥接 Codex 内置浏览器的凭证，也不控制普通 Chrome 的个人配置。用户明确指定匿名或其他凭证来源时，尊重该选择，不自动改用专用会话。

先复用对应分 P、语言的完整字幕缓存；缓存命中不启动浏览器、不请求登录。`collected_at` 是原采集时间，`cache_hit` 标明复用；需要更新时使用 `--refresh`。只读取缓存不能证明当前登录仍有效，不将缓存命中描述为“刚刚验证登录成功”。

采集器优先使用已安装 Chrome，在后台复用 `<项目根>/data/caption-browser-profile`。平台接口验证会话有效时直接获取字幕，不显示交接提示。仅实际需要认证时，日志返回 `LOGIN_URL http://127.0.0.1:.../login/...`；用当前浏览器工具可见地打开该页，确认标题“连接 B站字幕”和二维码实际显示。用户用 B站 App 扫码，在手机确认授权此本地采集器。脚本验证成功后自动采集，不要求再回复确认；用户说已登录时先读采集结果，不重复提问。

不要依赖原生 Chrome 窗口能否显示，也不要仅凭进程存在说“窗口已弹出”。二维码页面只监听本机回环地址，使用短期随机路径；显示登录进度，不展示 Cookie 值。二维码过期时重新启动采集并更新同一登录标签。已有会话有效时不会生成二维码或开启登录服务。

结果自动导入：stdout 是现有 `content/segments/origin` 格式；全文 JSON 和 SRT 保存于 `data/captions/<BV号>-p<分P>/`，JSON 返回这两个绝对路径。分 P 对应当前 `cid`；保留真实时间轴和末条时间 `coverage`。字幕文件可继续由 `fetch.py` 读取，用户无需手动选择文件。配图与整理仍由当前 AI 客户端完成。

请求仅获取元数据和平台字幕，不下载音视频或模型；登录数据保存在专用浏览器配置，接口请求使用内存中的站点凭证，不生成 Cookie 导出文件。平台限制或没有可下载字幕时返回具体错误，不自动转 ASR，不自动处理验证码。当前支持 B站完整 BV 链接及 `p` 参数；其他平台继续原有流程。

## 登录交接

1. 找到目标视频的标签；没有才创建内置浏览器标签。检查当前页面和完整 URL，短链接应确认最终视频。
2. 先检查该会话是否已登录，以及字幕能否直接读取。用户此前已登录且会话有效时，直接进入字幕获取，不重复提问、不重新打开登录窗口。匿名脚本失败不等于浏览器会话失效。确需重新认证时才显示该平台的正常登录界面。
3. 告诉用户“请在这个页面登录，完成后回复我”，用 `markHandoff()` 保留标签后等待。密码、验证码和扫码由用户处理，不结束掉登录页面。
4. 用户确认后查看同一标签，核实已登录及视频可访问；打开该视频的字幕/转录功能。只根据最新 DOM 或截图选择按钮。

登录态只按当前页面实际结果判断；不承诺永久保持登录，不要求每次重复登录。平台风控、地区限制、会员权限和没有字幕是不同情况，412 本身不能证明缺少登录。

## YouTube

内置浏览器当前提供 `tab.content.exportYouTubeTranscript()` 时，先打开真实 `https://www.youtube.com/watch?v=...` 页面。先确认播放器已载入目标视频；若在广告，使用实际显示的“跳过”按钮。广告阶段的字幕为空不能证明正片无字幕。展开描述，打开“内容转文字／显示转录文字”，核实面板实际返回结果，再尝试导出。

读取工具返回的本地文本文件，确认不是错误页、空文本或截断摘要。导出失败时查看当前页面的登录、验证或字幕限制；转写面板能读取全文时直接按段读取，包括滚动后续内容，不因导出接口失败就放弃。检查首句、末句和末尾时间，记录字幕语言以及是否自动生成。

如果工具仅返回纯文本，不猜时间轴；可从网页实际可见的带时间转录补充。标明自动字幕还是人工字幕，以工具结果/页面信息为准，不因为叫 transcript 就断言是 AI 字幕。

## B站和其他视频平台

检查该视频字幕菜单中的语言、AI 字幕和字幕列表/完整转录/下载入口。分 P 要对应当前 P。读取完整字幕列表并核对末尾时间；虚拟滚动列表需分段收集、去掉重叠部分。

先区分视频画面中的内嵌字幕、播放器的 AI 字幕轨，以及可导出的字幕文本；有内嵌字幕不能据此断言平台没有文本轨。已登录且 `ai-zh` 可用时不要再引导登录。若怀疑只是工具限制，查看当前文档提供的字幕导出能力与已观察到的字幕资源，不能仅凭抓取脚本的空结果下结论。当前工具不支持文本资源导出时，准确说明“字幕轨存在，但全文尚未取得”，不要改称“没有字幕”。

若网页只提供播放器当前一句 CC，没有完整列表或工具可用的导出入口，不能声称已经读取全视频字幕。报告“当前页面可显示字幕，但当前工具无法导出完整字幕”，再根据用户选择使用字幕文件、其他来源或显式允许的 ASR。不要自动把页面 AI 总结当字幕。

## 配图

根据已取得的真实时间轴定位关键内容，使用已观察到的播放器控件跳转；截图中应包含有用的课件/演示，不用广告、推荐栏代替。保存能力必须来自工具当前文档：优先媒体下载入口或 `pageAssets` 提供的已观察资产。使用截图时先阅读截图能力文档；没有本地路径时不编造文件。必要时改用明确标注的字幕示意图。
